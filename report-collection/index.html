方法论

MVP验证流程

所有系统统一遵循"安装 → 编排 → 验证 → 迭代"四步闭环，每个MVP周期控制在7天以内

Step 1 · 环境就绪（Day 0 ~ 0.5）
部署 OpenClaw（Docker 一键启动或阿里云镜像部署）→ 配置 LLM 接入（推荐阿里云百炼免费额度或 Ollama 本地模型）→ 安装 ClawHub 基础技能包（Python执行、文件读写、Web请求）
约0.5天
Step 2 · 核心技能开发（Day 0.5 ~ 2）
针对每个系统，从 ClawHub 搜索已有的开源 Skill（电商采集、图像处理、企微对接等），缺失部分编写自定义 Skill（纯 Markdown，告诉 AI 怎么做即可）。一条 Skill 就是一个 .md 文件，10分钟完成。
约1~2天
Step 3 · MVP验证闭环（Day 2 ~ 4）
用真实的最小数据跑通全链路：OpenClaw 接收输入 → 调用对应 Skill 处理 → LLM 分析/生成结果 → 输出验证。验证标准：端到端跑通即为MVP完成，不追求准确率、不优化性能。
约1~2天
Step 4 · 评估决策（Day 4 ~ 7）
基于 MVP 运行结果评估：业务逻辑是否跑通？用户体验是否可接受？数据质量是否达标？通过 → 投入正式开发；不通过 → 调整方向或放弃。
约1天

核心原则

🎯

砍到只剩骨架

MVP只验证"这个需求是否值得做"，不做性能优化、不做异常处理、不做高可用。能用就行。

🔄

Skill复用优先

ClawHub已有13000+技能，先找现成的。找不到再自己写。自定义Skill只需写清楚"输入→处理→输出"即可。

💰

LLM分级消费

简单任务用免费模型（GLM-4-Flash），结构化分析用本地模型（Qwen2.5-7B），复杂推理用廉价API（DeepSeek-V3）。绝不浪费token。

需求概述

质检员需人工解读光谱仪输出的谱图（拉曼/红外/紫外），判断样品合格与否。效率低、标准不统一、人员培养周期长。

MVP目标：输入CSV/图片格式的光谱数据 → 自动提取特征峰 → 比对标准谱库 → 输出"合格/不合格/疑似"结论。

OpenClaw技术方案

传统方案：Python + SciPy + PeakUtils + 深度学习模型 → 门槛高，需算法工程师

OpenClaw方案：

  • OpenClaw 调用 Python执行Skill 运行信号处理脚本（SciPy寻峰+平滑，10行代码搞定）
  • LLM 读取处理结果，直接判断是否合格（LLM懂谱图语义，不需要训练模型）
  • 标准谱库存为CSV文件，Skill 负责相似度计算

需求概述

客户希望看到宝石手串/项链戴在手上的实际效果，传统方式靠PS或想象。需要实现"上传手部照片 → 自动匹配宝石款式 → 叠加显示穿戴效果"。

MVP目标：用户上传一张手部照片和一款宝石照片 → 输出合成穿戴效果图。

OpenClaw技术方案

传统方案：Three.js 3D渲染 + MediaPipe手部追踪 + PBR材质 → 前端开发团队2~3人，开发周期1~2月

OpenClaw方案：

  • 方案A（最简）：OpenClaw 调用 图像处理Skill + LLM 生成 Python/PIL脚本，自动将宝石图叠加到手部照片
  • 方案B（进阶）：OpenClaw 调用 AI绘图API Skill（如FLUX/通义万相），输入"宝石手串穿戴效果"提示词直接生成
  • 两种方案均无需任何3D建模

需求概述

珠宝在淘宝/抖音/京东/拼多多等多平台销售，库存数据分散、手工同步费时费力。需要自动采集各平台销量、预测大促需求、预警库存不足。

MVP目标：自动拉取一个平台（如淘宝）的销量数据 → 用简单的趋势预测输出补货建议。

OpenClaw技术方案

传统方案：自研OMS系统 + 多平台API对接 + Prophet/LSTM预测模型 → 全栈团队开发2个月

OpenClaw方案：

  • 安装 ClawHub 的 电商采集Skill（32个国内电商Skills，一键安装）
  • OpenClaw 定时触发采集任务，数据落地到本地CSV/DB
  • 自定义 inventory-forecast Skill：写简单移动平均/线性回归进行趋势预测（不用Prophet，LLM自己就能算出趋势）
  • LLM 读取历史数据直接给出"建议补货量"

OpenClaw技术方案
