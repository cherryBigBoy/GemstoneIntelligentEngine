第一部分

需求分析报告

四大系统从业务背景、核心功能、技术架构到用户场景的全面需求梳理，聚焦落地可行性。

系统概述

珠宝玉石质检是行业关键环节。传统光谱仪数据分析高度依赖资深质检员的经验判断，一份样品从采集到出具报告平均耗时25~40分钟。本系统以传统信号处理 + 标准谱图库比对为核心技术路线，无需深度学习背景即可实现大部分谱图自动解读，将质检效率大幅提升。

针对"没有AI能力"的解决路径

谱图分析的本质是找特征峰+比标准库，可用 SciPy 的信号处理函数（find_peaks_cwt、Savitzky-Golay滤波）和 PeakUtils 库完成，无需深度学习。详见下文"技术落地路线"。

业务痛点

  • 人工解读效率低：一份光谱报告人工分析需25~40分钟
  • 判级标准不统一：不同质检员对相似谱图判级存在偏差
  • 数据孤岛：历史检测数据未有效积累，知识无法复用
  • 人才瓶颈：资深质检员培养周期3~5年，人才稀缺

核心指标

自动判级准确率
Phase 1（信号处理）: 80~85% · Phase 2（ML）: 88~92%
效率提升
单份报告：25~40min → ≤ 8min
技术门槛
Python基础即可起步，零深度学习入门

核心功能

  1. 光谱数据采集 — 对接主流光谱仪（拉曼/近红外/ICP-OES）数据接口，支持CSV/SPC等格式导入
  2. 信号预处理 — Savitzky-Golay降噪 + ALS自适应基线校正 + 归一化
  3. 峰识别与特征提取 — CWT连续小波变换寻峰，提取峰高/峰位/半高宽/峰面积
  4. 标准谱图库比对 — 基于GB/T 16552-2017建立宝石标准光谱库，余弦相似度匹配
  5. 质检报告生成 — 一键生成标准化PDF/Word质检报告
  6. 知识库积累 — 每次人工修正结果回流到数据库，持续改善匹配精度

关键工具链

  • SciPy.signal — `find_peaks_cwt()` 连续小波变换寻峰，无需训练数据
  • PeakUtils — 专做谱峰分析：峰高、峰面积、半高宽、峰匹配
  • PyRaman — 开源拉曼光谱处理库，含降噪/基线校正/标准化
  • 标准谱图数据 — 中国地质大学珠宝检测中心、GIA 公开宝石标准光谱可整理入库
  • After Phase 1 — 积累到一定标注数据后，用 scikit-learn 训练 SVM 分类器即可

系统概述

宝石交易的核心渠道已全面转向线上。本系统聚焦电商平台（淘宝/抖音/京东/小红书/拼多多）的库存管理，以大促日历驱动、销量脉冲预测、多平台库存同步为三大支柱，帮助商家在618、双11、年货节等大促节点精准备货、避免超卖/断货。线下门店协同仅保留查询层面的极简功能。

设计原则

线上为王：所有核心逻辑围绕电商渠道展开；大促为王：以促销日历作为核心时间轴驱动预测与备货；轻线下：仅保留门店库存查询，取消RFID硬件和多店调拨等线下重投入模块。

业务痛点

  • 多平台SKU割裂：淘宝/抖音/小红书各一套库存，超卖频发
  • 大促备货靠拍脑袋：618/双11应该备多少货凭感觉，不是缺货就是积压
  • 历史数据不利用：每年大促数据沉淀后无人分析，无法指导次年策略
  • 活动库存人工管理：大促期间多层活动价叠加，库存预占全靠Excel

核心指标

多平台库存准确率
目标：实时准确率 ≥ 99.5%
大促销量预测误差
目标：误差 < 15%（vs 人工估算 > 40%）
库存周转天数
目标：压缩 20~30%

核心功能

  1. 多平台OMS接入 — 对接淘宝/抖音/京东/小红书/拼多多API，实现商品与库存实时同步
  2. 大促日历引擎 — 内置618/双11/年货节/情人节/七夕等珠宝大促日历，支持自定义活动
  3. 销量脉冲预测 — 基于平销期基线 + 历史大促同期数据 + 流量波动特征预测未来销量
  4. 活动库存预占 — 按活动方案（满减/满赠/秒杀）预占库存，自动计算各渠道安全库存
  5. 智能补货建议 — 结合大促销量预测+当前库存+采购周期，自动生成备货建议单
  6. 大促复盘分析 — 活动结束后自动生成复盘报告：销量/库存周转/缺货损失/利润分析
  7. 轻量门店查询 — 仅保留库存可视化查询，供门店调货参考（取消RFID和全链路线下管理）

预测模型设计

销量预测 = 平销基线 × 大促脉冲系数 × 渠道权重 × 季节性因子
因子数据来源说明
平销基线过去90天日均销量(去除大促日)反映商品自然流量下的日销水平
大促脉冲系数同类商品去年大促倍率如618日均销量=平销期×3.5倍
渠道权重各平台历史销售额占比如抖音占45%、淘宝占30%
季节性因子珠宝行业季节性规律春节/情人节/婚庆季呈明显峰值

模型选型：Prophet（Facebook开源）适合有季节性的时序预测，一行代码出结果；后期可升级为LSTM。两种方案均无需深度学习背景。

系统概述

珠宝行业存在大量微信群/企微群交易场景，群内时常有人发布货源信息（如"出一批翡翠手镯，A货冰种，50只，打包价15万"），但群消息量大，商机容易被淹没。本系统7x24小时监控指定群聊，自动识别货物信息、主动私聊展开话术沟通、判断成单倾向后通知用户接入。

业务痛点

  • 群消息淹没商机：日均500+条群消息，人工筛选效率极低
  • 响应不及时：货源信息发出后10分钟是黄金沟通期，人工难以保证
  • 跟单话术不统一：不同销售跟进效果差异大
  • 人力成本高：全职群运营需2~3人

核心功能

  1. 群消息监听 — 对接企微API/WxBot，7x24监听指定群聊
  2. NLP货物识别 — 识别货物类目（翡翠/和田玉/彩宝等）、数量、等级、价格
  3. 自动私聊对接 — 货源发布后3秒内自动发起私聊
  4. 交易话术引擎 — 5阶段多轮对话（触达→询价→看货→议价→成交）
  5. 成单倾向评分 — 基于回复速度/议价深度/看货意愿等特征打分
  6. 用户介入通知 — 倾向≥80分即时推送+聊天摘要

技术架构

  • 消息接入：企业微信API / 微信个人号协议
  • NLP引擎：大模型API（豆包/DeepSeek）进行实体抽取，无需自训模型
  • 话术引擎：基于状态机的多轮对话管理框架
  • 倾向判断：规则引擎+简单分类模型双保险
  • 数据库：PostgreSQL（商机/话术/用户Profile）
  • 通知：企微应用消息/用户App push
